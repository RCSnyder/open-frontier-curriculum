# RFC 0001: Obelisk reconciliation and evidence ownership

Status: implemented engineering policy; architectural additions remain proposals.

## Problem

The staged Obelisk snapshot was assembled outside the legacy repository. It retained
the technical body but replaced navigation, validation and release metadata with
reduced versions. Generated routing views and rich teaching pages need distinct
ownership without competing canonical structures.

## Decision

Keep the six trunks and all existing IDs. Canonical JSON owns identities, relations,
source assignments and evidence attachments. Hand-authored exposition is attached
by path and stable target ID. Generated views expose the graph; they do not replace
teaching. Preserve imported snapshot directories as provenance, outside owned lint,
generation and release manifests.

Restore all 22 technical teaching attachments, the seven detailed specializations,
Frontier 100, legacy row counts and documentation rendering. Type the 63 interfaces,
preserving original labels where four ML/DR labels required semantic correction.
Add life routes and shared safety contracts without claiming routes equal competence.

## Alternatives and tests

Discarding the legacy pages would lose weekly practice and assessment. Keeping two
canonical trees would produce drift. Migrating all exposition into JSON would make
scholarly editing harder without strengthening evidence. The selected design has
explicit attachment checks, non-mutating drift checks and base-file comparisons.

No TS23/24/25 module is admitted in this RFC. Computation, networked software and
Earth/ecology have credible deletion failures but still need source-spined teaching,
prerequisite placement, compression trials and examiner review. DR remains provisional.
Its studio includes a compression probe, not a completed independent experiment.

## Maturity and sources

Sequential documentary gates distinguish scaffold, structured, source-spined,
taught and assessment-ready material. Higher review states require evidence records.
Source-spined means a resolved reading route, not verified scholarly adequacy.
Hash checking establishes file integrity, not reviewer independence or truth.
Missing node prerequisites remain visible instead of being invented to raise scores.

## Release boundary

The candidate version is `0.6.0-rc.1`; tooling package version remains `0.0.0`.
Restore frozen CI and separately gated Pages publication. Do not automatically
create tags while scholarly and maintainer release decisions remain unresolved.
Retain conventional-release configuration for a subsequent authorized release.
Legacy version labels in changelog history are historical, not current version inputs.

## Acceptance

- Preserved technical files compare to the fixed base without substantive loss.
- Unknown references, missing routes, cycles and fabricated review labels fail tests.
- Frontier CSV/JSON/page contracts agree, allowing only documented punctuation normalization.
- Generated audit, catalog and manifests reproduce without writes in check mode.
- Passing software checks do not promote empirical curriculum claims.

## Remaining authority

Maintainers must accept the release policy and domain reviewers must assess the
curriculum and source judgments. No remote publication, merge or commit is part
of this reconciliation session.
