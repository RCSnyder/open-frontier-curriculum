# Governance

Open Frontier Curriculum is maintained as an evidence-backed curriculum rather than a frozen syllabus.

## Decision principles

Maintainers should prefer changes that:

1. increase upstream leverage;
2. improve prerequisite closure;
3. strengthen proof-of-work;
4. replace vague requirements with executable ones;
5. improve source quality/currentness;
6. expose a failure mode;
7. reduce unnecessary breadth;
8. improve accessibility without weakening mastery.

## Review

Substantive RFCs should ideally receive three perspectives:

- a domain/technical review;
- a cross-domain systems/methods review;
- a safety, institutional, or human-systems review when deployment implications are material.

## Disagreement

A change may be merged with documented minority objections when the evidence is uncertain. The repository should preserve contested assumptions instead of manufacturing false consensus.

## Versioning

Major changes to the 136-week architecture should be recorded in `CHANGELOG.md`.

Frontier feasibility classes and current-source pages are expected to change more frequently than mathematical/physical foundations.
